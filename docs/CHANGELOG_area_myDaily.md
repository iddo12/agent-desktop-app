### My Daily on the configuration layer (text for the v1.121.0 release notes)

- **My Daily no longer assumes one computer.** Where its data lives, who "you" and "your partner" are, and which helper programs it uses now come from Setup / `app-config.json`. On the existing computer nothing changes: a migration config reproduces every old value (13 new entries in `tests/legacyParity.json`, checked by `tests/dailyConfig.test.js`, including the exact wording of every message My Daily sends to an agent).
- **The task list is optional.** Tasks, Decisions and the Tasks triage need the shared task folder, Python and the task tool (`tasks.py`). When one is missing the Tasks and Decisions tabs show a calm "The task list is off" card with a **Set up** button that opens Setup, and editing says "needs a one-time setup" instead of failing. Calendar, shopping lists, dates, mail accounts and shipments keep working with none of it. `python` and `tasks.py` are no longer assumed: Python is found on PATH (or chosen in Setup), the tool is `tasksTool`.
- **Data location.** A new install keeps its My Daily data in the app data folder (`userData/daily`). An existing computer keeps using the folder it already uses (`<agents folder>/daily`) until `userData/daily` exists, so nothing is lost or copied; `daily.dataDir` can pin it. A change of data folder takes effect after a restart.
- **Partner sharing is generic and OFF by default.** The sharing controls ("Send to ...", "... can see this entry", "Share my calendar with ...", "Added by ...") only appear when a partner name is set in Setup. A fresh install shares nothing; the owner's migration config keeps the old default (on). The stored names (`sharePartner`, `shareCalendarWithPartner`, calendar ids `owner`/`partner`, task field `needsOwner`, the tasks.py flag `--set-needs-owner`) are unchanged so existing data keeps loading; a neutral alias `needsUser` is also accepted on tasks.
- **Messages to agents use your name.** "<Name> answered GO to: ...", "Closed by <Name> via My Daily", the recommendation request and the task notes use the name from Setup (neutral "The user" and they/them until you set one; optional pronouns `daily.ownerPronouns` / `daily.partnerPronouns`).
- **Mail extras are off until configured.** The mail feed file, mail rules file, Gmail export file and "your own domains" no longer have built-in defaults; they come from the optional `daily` block of `app-config.json` (`mailFeedFile`, `mailRulesFile`, `gmailExportFile`, `ownDomains`) or the existing `DAILY_MAIL_FEED` / `DAILY_MAIL_RULES` / `DAILY_GMAIL_EXPORT` variables. The Gmail text no longer tells a stranger to "ask Security".
- Internals: `src/daily/dailyConfig.js` (all lookups, read once and cached), `src/daily/contract.js` and `src/renderer/daily-contract.js` (the only files that spell the stored legacy names), `tools/write-daily-migration.js` (adds the `daily` block to an existing migration config; run it after `write-migration-config.js`). My Daily is now marked wired in the feature registry.
