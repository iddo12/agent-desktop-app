## vNEXT - My Research: "How to improve" tab (2026-10-30, Security build, branch feat/how-to-improve)
A fourth tab beside Findings / My Recommendations / Skills & Plugins. Friction cards mined from the owner's own messages (`<sharedReports>\improve\cards.json`, written by the friction miner) with Yes / No and "Talk to <owner>".
- `src/improve/service.js` (main, no electron import, injected `dir` + `now`, async fs only): `load()` reads cards.json (<= 1 MB, <= 200 cards, every string clipped, <= 8 evidence quotes of 300 chars) and merges `decisions.json`; states missing / unreadable / too-big give a plain message, never an exception. Sort: new first, then by score. `decide(id, status, answer)` is the ONLY writer: it writes the sibling `improve\decisions.json` (`{updated, decisions:{<id>:{status, answeredAt, answer, times:{<status>:iso}}}}`), atomically (temp + rename), serialised, only for a card id that exists in cards.json, never touches cards.json, any CLAUDE.md or settings. Lifecycle guard: approved/rejected from new; rejected also from approved; applied only from approved; worked/didnt_work only from applied. When cards.json and decisions.json disagree the later lifecycle state wins. A damaged decisions.json is never overwritten (the writer refuses, the tab says so).
- IPC (main-research.js, inside `init`, same `needsSetup()` gate): `improve-load`, `improve-decide {id,status,answer}` (the tab can set approved / rejected / worked / didnt_work; `applied` is refused here: the Security agent applies a change and marks it applied by calling the service), `improve-write {id,agent,text}` -> the one shared writer with finding id `imp:<card id>`; `findRef` accepts it only for a real card whose `owner` is the addressed agent; week for the writer = current ISO week. preload: `api.research.improveLoad / improveDecide / improveWrite`. The renderer sends a card id, a decision and text, never a path.
- Renderer: `renderer/improve.js` + `styles-improve.css` (class prefix `hi-`, one CSS block, UI-UX mock `UI-UX\how_to_improve\mock.html`; tokens `--bg-panel --bg-app --border --text --text-muted --accent --rs-on-accent --rs-radius --rs-t-*`; new trio `--hi-info-*` defined in the sheet, dark under `body.dark`). Registered in `SUB_TABS` + `renderTabs` of research.js. Filters To decide / Approved / Applied, did it work? / Rejected / All; sections To decide, Approved, Applied, Closed (worked, did not work, rejected: shown 30 days after the answer). New and applied-checking cards start open (the latter needs a Yes/No); approved and closed start collapsed. Card title = first sentence of `finding` (cards have no title field). "Found <date>" = the file's `generated` date (cards carry no date of their own).
- Not in this build: before/after numbers on an applied card (cards.json has no such field yet); "reports on <date>" line.
- Tests: `tests/improve.test.js` (14: good/malformed/oversize/missing file, decisions writer, concurrency, lifecycle, damaged decisions file, findRef, wiring); `research.test.js` and `research-mag.test.js` IPC allow-lists updated for the three new channels.
