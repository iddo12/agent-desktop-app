## v1.121.0 - Setup panel and configuration layer (nothing is tied to one computer any more; IRIS needs your consent)

- New **Setup** tile (gear) in the Systems grid. It lists every optional feature (ARGUS, Memory, My Daily, Library, My Research, Tools, My Health, My Finance, PC Health, Voice, Shared fleet, IRIS, Keep going, Usage) with one of four states: Ready, Needs setup, Off, Needs attention (symbol + word, never colour alone, no red). One button per row; clicking it opens the row in place with the best folder already selected, a second click ("Create and turn on") does it. English and Hebrew (right-to-left); every word is in `src/renderer/setup-strings.js`.
- First run (no settings file, nothing detected, not a test instance): one welcome card with three choices (language, workspace folder, three starter features) and one Start button. It never appears on a computer that already has settings.
- **"Copy setup instructions for Claude"** copies a prompt with the settings file path, the format, every key and each feature's help, so an agent can set up a fresh computer. The same text is `SETUP.md` in the repo (generated by `node tools/gen-setup-md.js`; a test fails when it is stale).
- New configuration layer `src/appConfig.js`: `get / path / feature / isReady / set / setFeature / onChange`. Order: environment `AGENT_DESKTOP_<KEY>` > `userData/app-config.json` > auto-detect > none. Atomic writes, validated values (absolute paths, no `..`), never throws, no default points at any person's folder. Feature registry in `src/features.js`.
- **In this version no existing feature changes behaviour**: every feature is marked "works as before" and its code is not touched; later versions convert them one by one. A parity list (`tests/legacyParity.json` + `tests/legacyParity.test.js`) records the exact old hard-coded values and proves the settings reproduce them on the original computer; `tools/write-migration-config.js --from-legacy` writes that settings file at deploy time.
- **IRIS is off by default in every installation.** It starts (and listens on the local network) only when the person turns it on in Setup and confirms a plain-words dialog; the consent is stored as `iris.enabled` + `iris.consentAt` and can be written only by the app's own UI, never by the config API, agent instructions, environment or a hand-edited file. An install that already has a paired link keeps working with no step (a pairing is an explicit act): the first start records `consentSource: "existing-pairing"`. A missing, empty or corrupt pairing file means off. IRIS's own code is unchanged.
- Hard-code guard test (`tests/noHardcodedPaths.test.js`) scans the new files for drive-letter paths, personal names, site names and LAN addresses; builders add their converted files to it.
- Needs no restart for changes made in Setup. No new dependencies.
