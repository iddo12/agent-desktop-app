# v1.154.0 - THYRA "Questions for you": the asks in the same box as the permission prompts (2026-11-05, Security, branch feat/thyra-asks, not merged)

Owner (Iddo, 5 Nov): ONE window for everything that waits on him. The THYRA dock window (and the in-app pop-up, which shares the renderer) now has a second section, **Questions for you**, under the permission prompts.

- WHAT IT SHOWS: the open asks that agents register with `shared_tools\ask_iddo.py` (the same files the "waiting for you" bar lists: `list-open-questions`). Default view = asks created in the last 3 days, newest first; `Show older (N)` at the bottom reveals the rest (200 at most drawn). Row = agent, age, the question (3 lines, full text on hover or by clicking it), one button per quick answer. An ask with no quick answers is listed with the note "No quick answers: answer in the agent's chat." and no button.
- WHAT A CLICK DOES (same delivery as the inline cards, `answer-once.js`): main re-reads the ask FILE (through a file descriptor, because `syncGuard` can serve a copy up to 10 s old) and refuses if it is missing (answered/withdrawn), differs from what the dock drew (question, agent, quick answers, context, merav, created) or the label is not one of the file's quick answers. Then the main window's renderer types the label into the ASKING agent's chat as the owner's own message, seals it (`sealedAnswers`, via `button`, bound to the question that was shown) and moves the file to `answered\`. A refusal shows "Not answered: <reason>" (also when the row vanished because the ask was answered elsewhere). Success shows "Answered: <label> (sent to <agent>)" for 6 s.
- WHO CAN CLICK: only a real (isTrusted) click; IPC `dock-asks-list` / `dock-ask-answer` accept the main window and the dock window only (the dock's own preload has just those two calls, not the app's API). Buttons stay disabled for 1 s after the list changes (same settle as the prompt rows). Nothing is answered on a timer or without a click.
- COUNT: the chip ("Approvals N"), the collapsed tab, the tray tooltip and the dock window title count prompts + asks from the last 3 days (5 s refresh; the dock redraws when an ask appears or disappears).
- ALSO: `list-open-questions` is newest-first with cap 1000 (same text as the 2026-11-05 fix in the live checkout, so the two merge cleanly).
- CODE: `src/dockAsks.js` (pure: read, rows, check, answerFromDock), `src/renderer/thyra-asks.js` (the section), `approvals-popup.js` (hooks), `answer-once.js` (`dock-ask-deliver` handler + `sameAsShown`), main.js (IPC, badge timer), both preloads, `approvals-window.html` / `index.html` (script tag), CSS.
- TESTS: `tests/thyraAsks.test.js` (82 checks: 3-day filter and Show older, newest first, no 100 cap, stale/changed/label-not-in-quick refusals, delivery order type -> seal -> resolve in the real renderer file, untrusted click ignored, 1 s settle, notes), in `npm test`.
