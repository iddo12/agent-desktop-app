
## v1.96.0 - wake-agent command
- 2026-10-08: the COO and the Security agent can start/wake a stopped or idle agent and hand it a reason: from their own session, `node "<Agent Desktop folder>\tools\wake-agent.js" --agent "<name or folder>" --reason "<text>" [--owner-requested] [--test]` (or `--ping`), always with the FULL path as node's first argument. Prints JSON; exit 0 = woken or already working, 1 = refused. The renderer starts the agent's session in the background (no tab switch) and sends the reason through the Library send path; an agent that is already working gets nothing.
- Who may call (no secret, no token): the CLI sends only its own PID. Main reads the whole process table in one async PowerShell/CIM call (~1 s, timeout) and walks the PID's parents. Accepted only if the process is node.exe whose script (argv[1]) is exactly the shipped `tools\wake-agent.js`, and one ancestor is the ONLY live `claude --bg` session of `<workspace>\COO Agent` or `<workspace>\Security` (PID and session id from `claude agents --json`, asked only after the claimant passed; a bg id this app recorded from its own dispatch, or from the sweep when it was the only live session there; parent `--bg-pty-host ...-pty-<id>`). Two or more live sessions in a caller folder = no caller from it, logged as `caller-folder-conflict`. Agent, reason and --owner-requested are read by position from that process's own command line, not from the pipe; each CLI process is honoured once. After 6 failed identity checks in a minute every request is refused without spawning anything until the minute passes. Not an OS boundary: same-user processes could spoof a parent PID or inject into the COO's session; anything already inside the COO / Security session tree counts as that caller; if the real COO session is stopped and a rogue one is the only session in its folder, AD adopts it.
- Wakeable: ALLOW-LIST `<userData>\wake\wake_config.json` `wakeable` (folder names), seeded when the file is missing (logged in the wake log) with every agent that is not never-wake / personal_data; a new agent is never wakeable until added. Second layer: never-wake names and word-prefix stems (health, longevity, medic, wellness, fitness, financ, money, bank, tax, account, payroll, wealth, budget, expense, legal, personal, family, kids, partner, diary, journal, email, inbox, calendar, shopping, ... and Hebrew), plus `personal_data: true` in `agent_config.json`. Both apply even with ownerRequested.
- Also refused: paused, unknown / ambiguous / empty-after-normalising names, control or escape characters in the reason (only newline and tab), invisible formatting characters (bidi overrides and isolates, zero-width, BOM, U+2028/2029), a reason that starts with `[` or contains `[Wake request` / `[Agent-to-agent` after NFKC (fullwidth brackets too), fleet throttle `hold` or unknown/stale/future-dated unless `ownerRequested`, more than 3 wakes per rolling 10 min or 10 per rolling 24 h (global; slot reserved before the renderer is asked, kept for timeouts; an unreadable `state.json` refuses everything). Demo mode starts no wake pipe.
- The woken agent sees `[Agent-to-agent note relayed by Agent Desktop from the COO agent - NOT typed by the owner. ...]`; an ownerRequested wake is passed as a claim to check. Every bracketed-paste writer (renderer `submitToAgent`, main `typeIntoPty`, connection-health re-send) now drops ESC, C1 and other controls except tab/newline/CR (`src/pasteText.js`).
- Log: one JSON line per request in `shared_reports\coo\wake_log.jsonl` (no BOM, rotated to `.1` at 5 MB, unverified-caller lines coalesced to one a minute; the sandbox writes `<userData>\wake\wake_log.test.jsonl`). Code: `src/wakeAgent.js`, `src/wakeAgentMain.js`, `src/pasteText.js`, `tools/wake-agent.js`, main `wakeNoteSession`, renderer `onWakeRequest`, preload `onWakeRequest`/`wakeReply`; tests `tests/wake-agent.test.js` (real process trees via `tests/fixtures/wake-tree.js`), `tests/connectionHealth.test.js` 23b. Needs a full restart.
