# v1.137.0 - Wake-up watcher for Project Autopilot (2026-10-23, OFF by default)

- New: an idle agent is woken by one fixed line, `[[WAKE w-xxxx]] 2 new messages (from COO, Security). Read them, act, end with DONE:/BLOCKED:.`, when a mail marker in `<workspaceRoot>\shared_state\mail\<agent folder>\<id>.json` addresses it (markers are written by `shared_tools\projects\project.py` and, once registered, by `shared_tools\hooks\sendmessage_marker.cjs`). The line carries counts and sender folder names only, never marker content.
- Switch: `"wakeWatcher": { "enabled": true }` in `app-config.json` (a plain section, read with the new `appConfig.section(id)`; restart to apply). `"dryRun": true` logs what would be sent and types nothing. Default OFF; nothing in the app changes while it is off.
- Code: `src/wakeWatcher.js` (pure decision: gates, rate limits, loop protection, single-flight, heartbeat), `src/wakeWatcherMain.js` (I/O glue: marker reading, persisted memory in `<userData>\wakewatcher.json`, 30 s sweep + fs.watch with 2 s debounce), `main.js` `startWakeWatcher()` (20 s after ready; facts from the live sessions; delivery = `deliverToAgentVerified`, the Keep-going path). Tests: `tests/wakeWatcher.test.js` (31), `tests/wakeWatcherMain.test.js` (9).
- Safety: wakes only attached agents that are idle (transcript quiet 20 s), screen known, no dialog, input box empty, no handoff running, not paused, nobody typed to it in 60 s, throttle GO/SLOW, no CPU/load hold; max 6 wakes/agent/hour, 30/fleet/hour, 20 s fleet gap, 60 s agent gap (config can only tighten); one wake per marker (handled ids persist across restarts); first sight of an agent records its existing markers as seen (enabling never wakes the fleet); unconfirmed delivery is never retried, a definite non-delivery retries once after 3 min; hop limit 4 and ping-pong pause (log events, nobody is messaged); never-wake list reuses `wakeAgent.isNeverWake` (health/finance/legal/personal stems) plus `personal_data` agent flag. It never types anything the owner would have to approve and sends nothing on the owner's behalf.
- Not wired yet: heartbeats (no "work that needs nobody" feed), `*_pending_notes.md` input, ledger "ready task" input (project.py already drops a marker for those). Stopped agents (no attached session) are not woken; they read their mail at the next start.
- Also: `SETUP.md` (generated from `features.js`) gained one paragraph on the `wakeWatcher` section.
- CLAUDE.md (main tree, not edited by this branch): add this entry when the branch is merged.

## Review fixes (same version)
- Hook hop limit: `sendmessage_marker.cjs` now walks back past tool results and wrapper entries (task-notification, system-reminder, "[SYSTEM NOTIFICATION", "Another Claude session sent a message") to the real prompt and looks for the `[[WAKE ...]]` line in its first 20 KB (was: newest user entry, first 400 chars), so a chain's hop no longer silently resets to 0.
- Hook skips `uds:` pipe addresses explicitly (documented in its header): no pipe-to-agent map is built, so sends by address leave no marker from the hook; for those the watcher relies on the `project.py` markers. Only sends by agent name get one.
- `terminal-input` handler: `lastHumanInputAt` is set only when the input is not app-originated (`!fromApp`); xterm replies, Keep going and handoffs no longer count as a person typing.
- Hop-stop / pair-pause lifting by ledger events is scoped to the two agents of the chain (receiver and sender; newest event per agent from `events.jsonl`, names matched case-insensitively, "Foo Agent" == "Foo") instead of any ledger event anywhere. The fleet-wide value is kept only for ping-pong detection.
- `projectsDir` is derived from `workspaceRoot` (`shared_state\projects`, like the mail dir default), no longer from the `wakeWatcher.mailDir` override.
- Tests: wakeWatcher 31 (hop-lift case extended), wakeWatcherMain 10 (+1), hook 7 (+2).

## Review fixes, round 2 (same version)
- Hook transcript window: if the newest 256 KB holds no real user prompt and the file is larger, the hook now reads 1 MB and then 4 MB tails; if the prompt is still out of reach it returns hop 3 (maxHop - 1), never 0, so a long turn with big tool results cannot reset the chain. A whole file with no prompt in it is still hop 0. The first (possibly cut) line of a partial window is ignored. Hook tests: 8 (+1).
- `project.py` markers: `mail_marker` now stamps `hop = (hop of the sender's newest wake record in <mail>\_wakes written by this watcher, within 3 h) + 1`, else 0 (sender matched case-insensitively, " Agent" suffix and path prefix ignored). Chains started from project.py markers can therefore reach the hop cap. `test_project.py`: 7 tests (+1). Still not enforced: the hook skips `uds:` addresses, so a send by address leaves no hook marker; the per-agent/fleet rate caps are the backstop there.
- Human-input accounting: automatic senders now pass `{ app: true }` (Esc interrupt in `guards.js`; Esc and Enter in `renderer/connection-health.js`; the Enter nudges, the post-paste `\x1b[201~`/Enter of a send and the press-Enter/send-keys handlers in `renderer.js`; the handoff nudge Enter in `guards.js`). Verified in the `terminal-input` handler: `app` also arms `connHealth.noteWrite` and the dead-attach check, but `noteWrite` ignores keystroke-only data (less than 3 printable characters) and the dead-attach check needs a `\x1b[200~` paste, so these key writes have no other side effect. The recovery ladder's re-typed message (starts with `\x1b[200~`) would arm `noteWrite`, so it uses a new `{ auto: true }` flag instead (preload forwards it; main skips `lastHumanInputAt` for `app` or `auto`). Voice-command keys and xterm `onData` stay human. Test: source-wiring test in `wakeWatcherMain.test.js` (11, +1).
